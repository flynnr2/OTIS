# Current firmware/host contract

The canonical JSON file retains its schema-format filename but now declares
`OTIS_FIRMWARE_HOST_CONTRACT_V2`. The generated C++ projection is regenerated by
`tools/generate_firmware_host_contract.py`. This is an incompatible replacement;
old SETUP, ARM, LEASE, EVIDENCE and unbound ABORT commands reject as unknown.
Historical captures retain their original contract and reader revision.

Canonical D14/D8 raw records and the usual measurement stream retain their
existing layouts. Instrument authority is independent of delivery and recording.
Ordinary serial output uses bounded complete-record staging and whole-frame
ownership. Queue exhaustion discards output and increments delivery-loss counters;
it does not invalidate capture or inhibit qualified control.

`ACTIVE?` and `ACTIVE SNAPSHOT <nonce>` request current state. Periodic STS cohorts
use component `adaptive_hybrid`, contract `OTIS_INSTRUMENT_STATUS_V2`, and matching
`snapshot_generation_begin` / `snapshot_generation_complete` markers. An incomplete
cohort cannot establish a current snapshot. Status reports requested/effective
mode, reason, fault, known-code provenance, DAC epoch, command completion, operating
deadline, reference qualification, response incompleteness and cumulative delivery
loss. USB FIFO acceptance cannot prove host retention.

The sole mutating form is:

```
ACTIVE MODE <boot_session_u64> <command_sequence_u32> <mode> <code> <dwell_s>
```

Modes are 0 AUTO_DISCIPLINE, 1 OBSERVE_HOLD, 2 FIXED_CODE, 3 CHARACTERIZE. AUTO
accepts dwell zero for indefinite operation or 1..604800 seconds for an explicit
firmware-owned timed stop into HOLD. HOLD requires code/dwell zero. FIXED_CODE
requires a code within A800..AB00 and dwell zero. CHARACTERIZE is one step at most
21 codes from the confirmed code, with dwell 1..86400 seconds, then HOLD. Hold
commands have a reserved internal lane. No command changes USB ownership or
resets the board. Duplicate exact requests cannot repeat an actuator effect.

Boot identity is a nonzero 64-bit randomized nonce from the RP2040 SDK entropy
and PRNG facility, separate from the 32-bit measurement capture session. Randomized
identity has a residual collision possibility; it is not a persistent cross-reset
counter. A zero nonce inhibits startup. Every cold/warm firmware boot establishes
a new session and explicitly writes the single versioned startup code A84D.

New records use schema version 2 and a shared session-scoped `record_sequence`
assigned before possible output loss. The JSON is authoritative for field order
and types:

- ICM: exact command receipt; ACCEPTED means pending/effective selection, not DAC
  application. Status `command_completed` establishes completed identity.
- IWR: released internal write, capture/session identity, prior/requested code,
  DAC epoch, source decision or command, kind and exact execution deadline.
- IAP: exact executor result, attempted/succeeded facts, accepted identity and
  explicit no-write rejection reason.
- IDC: decision source span and phase, qualification inputs, numerical policy
  outputs, requested delta, and retained frequency/phase debt.
- IRS: scientific response classification and exact post-application source span.
- IST: mode, state, reason and qualification transitions with source frontiers,
  known code/DAC epoch and response incompleteness.

All new execution coordinates use `rp2040_timer_us64`, the native extended RP2040
microsecond timer sampled by `time_us_64()`. These are application/service
coordinates, never hardware edge-latch timestamps. Raw capture coordinates and
accepted-reference reconstruction retain their separate declared domains.

Core 1 retains a single transaction independently of telemetry, releases it through
an internal mailbox, and consumes the exact Core 0 result. Core 0 consumes each
identity before one bounded DAC attempt. Before a correction it rechecks current
same-receiver qualification, platform state, prior known code and deadline. Both
frequency and phase consumers receive the applied code/epoch before owner commit
and before the next dependent capture decision. A host never releases this path.
